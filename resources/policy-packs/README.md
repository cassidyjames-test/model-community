# Policy Packs

Policies and related prompts to be adapted and used with policy-following open safety models.

## Contributing

Before contributing a policy, we recommend reaching out by [opening an issue](https://github.com/roostorg/model-community/issues/new/choose) or chatting with us in [#model-community-rmc in our Discord server](https://discord.gg/UXmBqy7kFX) to make sure it's a good fit. Once you're ready to contribute, you can open a pull request to add your policies as Markdown files.

If you are not familiar with the process of contributing to an open source project on GitHub, you can follow these directions:

1. **Sign up for a [GitHub account](https://docs.github.com/en/account-and-profile) account**: Contributing currently requires an account with GitHub. We recommend choosing a username that will be recognizable or memorable as _you_ to others in the ROOST community, but you can also use a pseudonym.

2. **Navigate to the [policy-packs folder](https://github.com/roostorg/model-community/tree/main/resources/policy-packs)** on GitHub if you're not already there. If your organization already has a folder, select that folder to navigate into it.

3. Select **`Add file ⏷`** → **`+ Create new file`** at the top-right of the page.

4. Focus the **`Name your file…`** text field near the top of the page.

   1. **If this is the first policy from your organization**, type your organization name (lowercase, dash-separated) and then `/` to create a new folder for it. If you're already in a folder for your organization, skip this and continue to 4.ii.

   2. **Type a concise filename for your policy** (lowercase, dash-separated), ending with the `.md` file extension; for example, `tvec.md`. If you plan to contribute multiple related policies, you may use the same method as 4.i. to create subfolders, or just name the files similarly (e.g. `tvec-definitions.md` and `tvec-actors.md`).

5. **Type or paste your policy** as [Markdown](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax) into the text area (where it shows `Enter file contents here`). To confirm the Markdown formatting is working as intended, you may switch from `Edit` to `Preview` using the view switcher at the top.

6. **Select the green `Commit changes…` button** at the top-right to propose your changes.
